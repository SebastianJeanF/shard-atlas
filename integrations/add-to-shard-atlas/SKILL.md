# Add to Shard Atlas

Read `static/ai-instructions.md` in the Shard Atlas checkout. This skill is stored at `integrations/add-to-shard-atlas/SKILL.md`, so the guide is `../../static/ai-instructions.md` relative to this file's real location. Resolve an installed symlink before locating the checkout. It defines the supported route, schema, source attribution, topic reuse, relationship direction, and verification requirements. If local files are unavailable, retrieve the guide from the user's source repository through an available GitHub connection, or use the guide copied from **Use with AI** in the app. Disclose missing access rather than assuming a particular machine or installation path.

Interpret “this” using the relevant current conversation or supplied source. Shard Atlas stores technical understanding: programming languages, computer science, mathematics, and ML or AI theory. Capture reusable explanations, definitions, exact code, examples, and caveats. Exclude world news, company announcements, model-release news, compensation, career tracking, and forecasts. For mixed material, save the technical knowledge and report what was excluded. If it contains only news, explain the scope and suggest History Atlas without writing there automatically. The explicit add/save request authorizes additions to the local knowledge collection and useful connections within that scope. It does not authorize unrelated edits, deletions, source-code changes, or sending content to other services.

Before preparing notes through the local `shard_atlas` server, call `shard_atlas_get_instructions` and read its full content. Apply the five authoring rules in the guide, including honest example validation and a reason for each release assignment. Then use `shard_atlas_search`, `shard_atlas_read`, and `shard_atlas_add_knowledge`. Pass the returned `version` as `instructionsVersion` alongside the unchanged batch. If the guide changes or the tool session restarts, fetch and apply the current guide again before retrying with the same request ID and batch. Search and read likely matches before saving. Reuse existing topics and complementary notes. Preserve code, sources, caveats, and uncertainty. Do not mark knowledge as confident without evidence from the user. Add meaningful relationships with reasons, using the correct direction.

If the MCP tools are unavailable but local execution is available, use `tools/shard_atlas_client.py` in the project. Run its `instructions` command and read the full guide before preparing a contribution. Use `--help` for current syntax. It locates or starts the correct local service without opening a browser. Do not write directly to the database or modify seed/source files to add knowledge.

For academic material, preserve the guide's optional `subjects`, `courses`, `notation`, and `assumptions` metadata. Keep one reusable concept with several course or lecture occurrences when appropriate. Verify source locations, distinguish course-specific notation and assumptions, and leave unknown details empty. Do not imply that a source URL was read or that the app automatically extracts concepts from PDFs.

Preserve useful structured `perspectives`, `walkthroughs`, technical `comparisons`, and explicitly recorded `learningLog` entries when supported by the supplied material. Do not invent a learning timeline, prior misconception, or resolution. Keep manual `verification` independent of personal understanding: `source-checked` requires a supported check, a note, and a source URL or location. Personal `status: verify` means **Needs clarification**. Use content verification for unchecked or incorrect claims. Keep connection scope, evidence, source URL, and source location when available, without strengthening the source's claims.

Preserve optional `experiments` setups using the guide's typed `gradient-descent` or `value-iteration` configuration and `algorithmVersion: 1`. Keep IDs, source attribution, and any complete same-type comparison configuration stable. These deterministic finite educational models need no random seed and do not run supplied code. A simulation is not source verification or evidence of personal mastery. Runtime preview changes are not saved knowledge until an explicit configuration or normal shard save.

Give each add request and new note stable IDs. Preserve the exact request ID and payload when retrying after a timeout. Read the actual saved IDs from the receipt and verify the notes and links. If a replay warns that content changed or was deleted after the original save, preserve the later user changes and report the current state. Report titles added or reused and useful connections. Do not treat an attempted write, generated file, or app launch as proof of a save.

When the chat has no local access, produce the complete portable JSON file described by the guide. Use verified IDs from a supplied export when available. Tell the user the file is ready for **Use with AI → Preview a file**. Include actual image bytes as archive assets when photos or diagrams are available and useful, following the guide. The user can review the rendered cards and photos, select cards, and edit proposed details before saving. Changes automatically refresh validation. Reusing a saved card preserves its explanation, courses, and notation. Adding new course context to it requires an explicit edit afterward. Never claim a direct save in this fallback.
