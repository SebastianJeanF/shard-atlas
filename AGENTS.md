# Working on Shard Atlas

The canonical source now includes the website and Mac app. Read `docs/cross-platform.md` and `docs/handoff.md` before cross-device work. Edit the shared interface under `static/` and browser-only behavior under `web/`. Generate browser output with `npm run build:web`, then build the hosted Worker with `tools/build_host.py`. Preserve the existing owner-private Sites project. Never commit `web-dist/`, `dist/`, `hosting/public/`, private Drive settings, cloud credentials, or personal collections. Source changes that affect knowledge semantics must pass both Python and browser checks. Native bundled changes still require a Mac rebuild. Do not replace or advance a sync base while a local edit or a different cloud revision is unreviewed.

For every application update, follow [Efficient updates and verification](docs/cross-platform.md#efficient-updates-and-verification) automatically. This is a standing workflow, so the user does not need to repeat it in each request. Reuse valid evidence and isolated QA tooling, parallelize independent checks, and preserve the final correctness gates. Documentation-only changes need documentation checks, with no application rebuild or publication unless they affect generated runtime content.

On this Mac, maintain the checkout at `~/Developer/shard-atlas` and the installed app at `~/Applications/Shard Atlas.app`. Keep dependencies, builds, Sites source mirrors, browser test profiles, and QA evidence outside Drive-backed folders. `~/Documents` is configured for Drive backup too. Use `~/Library/Application Support/Shard Atlas Maintenance` for private maintenance artifacts. The former `My Drive/Projects/shard-atlas` location is only a small compatibility bridge for older AI helpers. Do not install dependencies, rebuild an app, or store databases there. Preserve and refresh its exact authoring guide while old helpers still need it. Do not use a directory symlink from Drive into the maintained checkout. The working library and ordinary local backups remain under `~/Library/Application Support/Shard Atlas`. Other devices should also use their own local checkout outside synchronized folders.

When asked to add or save knowledge, first read `static/ai-instructions.md` and use the `add-to-shard-atlas` skill or local contribution tools. This is a knowledge operation. Do not modify app code, starter notes, the public release catalog, or SQLite directly to add personal knowledge. Search existing notes, retain source attribution and uncertainty, reuse suitable topics, add meaningful connections, and verify saved content. Requests to modify the application itself follow the development guidance below.

Preserve user knowledge. The default working database is under `~/Library/Application Support/Shard Atlas`, outside the source checkout. Never use it for automated or destructive tests. Use temporary databases and make a consistent SQLite backup before changing a real database schema or importing existing knowledge.

Shard Atlas focuses on technical understanding: programming languages, CS, mathematics, and ML or AI theory. The current personal collection is C++. News, company announcements, career and compensation tracking, and forecasts belong outside this atlas. Preserve legacy storage and archive compatibility for recovery, but do not reintroduce retired news, entity, comparison, inbox, or Ask interfaces. Topic map replaces the manual Canvas with automatic topic neighborhoods, overlapping memberships, and expandable typed relationships. Keep every useful topic membership and distinguish shared-topic links from saved conceptual connections. Hide broad organizational tags by default with an option to show them. Layout must be deterministic for the same data and view settings. Legacy board data remains in storage, archives, and backups for recovery. Preserve imported Lucid knowledge, source attribution, and relationships.

The standalone Connections page is retired. Keep relationship creation and editing, the Library's compact preview, and the Topic map's focused relationship explorer without reintroducing the collection-wide Connections page.

The user prefers a local app with an attractive interface and source that an AI can maintain. The Python storage service uses only the standard library. KaTeX is vendored for offline math rendering with its license. Preserve stable shard IDs, typed relationship direction, portable exports, revision history, trash, images, drafts, and legacy recall data. Recall must not reappear in the interface. Keep starter content separate from personal data. Do not reseed a collection that the user emptied.

Follow the user's supplied editorial standards when writing documentation. Preserve exact C++ source text in rendering and the established syntax palette. Unresolved identifiers should remain neutral. Do not commit private editorial documents or identifiers into this source repository.

Verify changed user workflows in a real browser, including narrow screens when layout changes. Keep test notes and screenshots out of the user's working collection.
